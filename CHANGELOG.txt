Mineralogy 6.1.2.2602001 for Minecraft 26.2

- Ported the accepted Mineralogy 6.1.2 Forge contract to Minecraft 26.2 while
  preserving every registry and block-entity ID, NBT field, item definition,
  recipe identity, configuration key, migration report, provider rule, locale,
  guide, crude-oil identity, relief shape, mining tag, and furnace-state fix.
- Updated the main and integration-test data packs to data format 107.1 and the
  external texture packs to resource format 88.0.
- Aligned the five changed vanilla overrides with Minecraft 26.2 by omitting
  the removed `category` field from furnace, brewing stand, and coast, sentry,
  and vex armor-trim template duplication recipes. IDs, conditions, patterns,
  ingredients, results, counts, and advancement behavior remain unchanged.
- Kept Minecraft's new sulfur and cinnabar families separate from Mineralogy.
  Vanilla materials are not aliases or inputs for Mineralogy sulfur dust,
  storage, recipes, tags, or its established OreSpawn rule.
- Retained 1,433 JSON recipes and progressive advancements, 18 reversible slab
  bridges, 48 Minecraft recipe overrides, 21 advancement overrides, 19
  configurable cobblestone routes, the native tuff matrix, stone-spear
  compatibility, and Mineralogy slab precedence.
- Retained the schema-4/revision-3 OreSpawn provider with 32 rocks, three ores,
  the covered Ocean oil deposit, native aliases, stone/deepslate hosts,
  Cyano/GEOME migration, and `manage_vanilla_ores=false`.
- Upgraded the build and runtime target to Forge 65.1.0, Java 25, released
  OreSpawn 4.0.16.2602001, and Maven coordinate
  `zone.moddev.mc:Mineralogy:6.1.2.2602001`.
- Reused the checksum-sealed five-file Mavenizer fixture as an audited
  zero-repair Forge 65 target. Forge 65 still exposes its compile-only
  `mixinextras-common` artifact beside the embedded MixinExtras runtime on
  Buildship's combined launch module path, so Mineralogy excludes the redundant
  common artifact and audits the compile classpath to prevent startup failure.
- Retargeted guarded branch CI, cold bootstrap, artifact checks, documentation,
  and tag validation to Minecraft 26.2 and exact tag `6.1.2.2602001`.

Mineralogy 6.1.2.2601021 for Minecraft 26.1.2

- Ported the complete Mineralogy 6.1.2 content, recipe, migration, and
  compatibility contract to Minecraft 26.1.2 Forge while preserving every
  registry ID, block-entity ID, NBT contract, asset, configuration key,
  provider rule, locale, guide, and crude-oil identity.
- Retained the corrected relief occlusion shape, all 928 item definitions, and
  the fixed mining tags: 1,133 pickaxe-mined blocks, 123 iron-tier blocks, and
  329 stone-tier blocks use target-supported optional entries inside `values`.
- Retained warning-free rock-furnace lit/unlit transitions and adapted
  inventory, fuel, cooking progress, block-entity persistence, components,
  enchantments, fluids, rendering, events, and recipes to Forge 64 APIs.
- Retargeted required legacy-conversion Mixins to Minecraft 26.1.2. Chunk
  conversion now intercepts the four-argument `SimpleRegionStorage` method and
  protects legacy Overworld chunks stored in either the historic root `region`
  directory or `dimensions/minecraft/overworld/region`, without rewriting the
  source save before normal loading.
- Preserved all 18,192 pre-flattening mappings, selected-world recovery,
  sidecars, furnace normalization, and populated-boundary protection.
- Preserved 1,433 JSON recipes and progressive advancements, 18 reversible
  native/Mineralogy slab bridges, 48 Minecraft recipe overrides, 21 Minecraft
  advancement overrides, all 19 configurable cobblestone routes, the native
  tuff matrix, stone-spear compatibility, and Mineralogy slab precedence.
  Minecraft 26.1's exact stone-to-cobblestone stonecutting recipes remain
  untouched, and obsolete stonecutting `group` fields are not emitted.
- Reapplied configurable cobblestone holder sets after Forge 64 commits static
  registry tags, preserving unrelated members and relying on holder-set
  invalidation callbacks for already-parsed ingredients.
- Retained OreSpawn schema 4/provider revision 3 with 32 rock rules, three ore
  rules, native aliases, stone/deepslate hosts, the covered Ocean crude-oil
  deposit, Cyano/GEOME migration, and `manage_vanilla_ores=false`. Mineralogy
  registers no parallel world generator.
- Updated the human guide bundle for Minecraft 26.1.2, Forge 64.0.9, released
  OreSpawn 4.0.16.2601021, Java 25, resource format 84.0, data format 101.1,
  and the target's namespaced Overworld storage layout.
- Added reproducible Java 25 main, sources, and Javadoc artifacts under
  `zone.moddev.mc:Mineralogy:6.1.2.2601021`, exact OreSpawn dependency
  verification, guarded 26.1.2 CI, and tag validation for `6.1.2.2601021`.
- Reused the checksum-sealed MinecraftMavenizer 0.5.21 compatibility fixture as
  an explicit zero-repair Forge 64.0.9 target. Mavenizer, Gradle, compilation,
  tests, and launches all use pinned Temurin 25.0.3+9; fixture files remain
  build-only and are rejected from release jars.
- Excluded Forge 64's compile-only `mixinextras-common` artifact from the
  Mineralogy dependency model so Eclipse does not place it beside Forge's
  embedded MixinExtras runtime and fail Java 25 module resolution at startup.

Mineralogy 6.1.2.121111 for Minecraft 1.21.11

- Updated all pickaxe and harvest-tier tags to Minecraft 1.21.11's optional
  tag-entry object format. This restores normal mining speed and drops for all
  1,133 pickaxe-mined Mineralogy blocks, including every derived rock form.
- Synchronized a retained rock-furnace block entity with its new block state
  before reattaching it during lit/unlit transitions, removing the chunk state
  mismatch warning while preserving fuel, contents, and progress.
- Added Minecraft 1.21.11 item definitions for every registered Mineralogy
  item and block item, restoring their inventory, hotbar, recipe-book, and
  creative-tab models. Block items now explicitly retain their translated
  `block.mineralogy.*` names under the target's new item-construction rules;
  the crude-oil bucket uses its established static texture to avoid mixing the
  target's separate item and block atlases.
- Delegated terrain, strata, ore, and covered fluid-deposit generation to the
  released OreSpawn 4.0.16.121111 provider engine, retaining the supported
  `[4.0.6,5.0.0)` range; removed Mineralogy's parallel
  geology, geome, ore, noise, and stone-replacement generators.
- Retained all four ore host families plus explicit vanilla stone and
  deepslate hosts, avoiding Forge 61's unbound-tag phase during OreSpawn's
  packaged-provider discovery.
- Preserved established OreSpawn profiles containing tag-backed ore hosts by
  deferring their pre-tag common-setup lookup; the same unchanged profile is
  rebaked normally after server tags load.
- Preserved all world-facing registry, tile, NBT, recipe, asset, patch, and
  pre-flattening conversion identities while moving production packages to
  zone.moddev.mc.mineralogy. Existing 1.10/1.12 chunks are protected during
  1.21.11's flattening conversion. Legacy rock-furnace IDs are established
  before Mojang data fixing, then all pre-namespaced tile IDs are made safe
  before Forge constructs tile entities, so inventories and progress survive
  and an uppercase vanilla ID cannot abort the complete chunk load.
  Legacy state tables now support the complete 12-bit mod block-ID range in
  both development and packaged runtimes, and each selected save reinstalls
  its own numeric mapping after the client enumerates multiple old worlds.
- Added compatibility-safe controls for drywall, rock-salt lamps, mineral
  dusts, and fertilizer, plus the stable five-way grouped creative tabs.
  Disabled content remains registered and usable in established worlds.
- Preserved vertically mounted legacy rock-salt lamps on torch-supporting
  blocks such as fences during pre-flattening world conversion.
- Corrected relief occlusion so their intentionally open centres reveal the
  supporting block face instead of culling it and exposing the sky/void when
  mounted on floors, walls, or ceilings.
- Made the historical `COBBLESTONE_EQUIVILENT` option functional through
  target-native per-family block and item tags, including vanilla aliases,
  reapplied after data reloads by updating the exact immutable tag objects
  retained by already-parsed Forge 61 recipe ingredients. Canonical `c:` tags
  and legacy `forge:` aliases are updated together; chert and pumice
  remain unconditional cobblestone equivalents.
- Added isolated Mineralogy crude-oil source and flowing fluids, block, bucket,
  rendering resources, and the covered Ocean deposit declaration.
- Uses Minecraft 1.21.11's native granite, diorite, andesite, basalt, and tuff for
  new OreSpawn terrain while retaining Mineralogy's historical registrations
  and conversion aliases. Native smooth basalt joins Mineralogy's smooth-basalt
  family without replacing Minecraft's basalt-smelting route. Deepslate remains
  a terrain and ore host rather than becoming a construction family.
- Preserved rock-furnace save recovery and novaculite's 3/15/1 properties;
  corrected replacement drop semantics and exact full-block Silk Touch results
  for double slabs.
- Ported the accepted recipe contract as 1,433 native JSON recipes and matching
  advancements: safe 4-to-1 mineral packing, charcoal and Base Metals dust
  gunpowder routes, exact slabs, slab recombination, construction-form brick
  conversions, progressive sand polishing, matching-slab rock furnaces, and
  blank-to-marked relief progression. Each rock-furnace recipe is revealed as
  soon as its matching slab is acquired, before a vanilla furnace is crafted.
- Reconciled Minecraft's native andesite, basalt, diorite, granite, and expanded
  tuff family with
  their retained Mineralogy world-compatibility blocks. Native blocks now
  unlock and feed every non-conflicting matching Mineralogy recipe. The five
  vanilla polished-block recipes are replaced by block-plus-sand routes so
  the 2x2 recipes remain available for Mineralogy bricks. The six shared
  andesite, diorite, granite, and tuff slab recipes plus all fifteen matching
  stonecutter routes now produce Mineralogy's more capable slabs, while the
  vanilla slabs remain registered and tag-compatible. Eighteen exact shapeless
  compatibility recipes convert each raw, polished, or tuff-brick Mineralogy slab to its matching vanilla
  slab and back at a lossless 1:1 ratio for modpacks that require an exact
  vanilla item. Native tuff stairs, walls, bricks, polished forms, and chiseled
  blocks retain their vanilla routes; reversible slab bridges preserve access
  to the chiseled recipes. Recipe advancements use the same exact item or
  family tag as the recipe they reveal.
- Extended Minecraft 1.21.11's native stone crafting and tool-material tags so
  every enabled cobblestone equivalent, including all 27 legacy rock families
  and target-native aliases, works in the complete vanilla contract. Nineteen
  conditional JSON overrides cover furnaces, brewing stands, redstone and
  conversion recipes, and all stone tools without changing their IDs,
  patterns, outputs or other ingredients. Disabled mode restores the native
  ingredients and keeps blackstone, chert and pumice valid. Matching-slab
  rock-furnace upgrades and vanilla cobblestone construction recipes remain
  distinct.
- Kept Minecraft's new stone-spear recipe and advancement authoritative. Its
  native stone-tool-material tag automatically accepts enabled Mineralogy rock
  families, while disabled mode retains vanilla materials plus unconditional
  chert and pumice; no recipe or advancement override is shipped for it.
- Added conditional overrides for the coast, sentry, and vex armor-trim
  template duplication recipes. Enabled mode accepts the Mineralogy
  cobblestone union; disabled mode restores exact vanilla cobblestone. Their
  existing template-owned advancements remain untouched.
- Added `sends_telemetry_event: false` to every generated recipe advancement,
  including all conditional Minecraft advancement branches.
- Prevented Forge 61 from silently reducing optional carbon- or coal-dust
  gunpowder recipes to nitrate plus sulfur when their compatibility tag is
  empty; every loaded gunpowder recipe now requires all three components.
- Added 17 reviewed UTF-8 JSON locales with the same 938 ordered keys, including
  Brazilian and European Portuguese, Canadian French, Japanese, Korean, and
  Russian.
- Added first-start player, developer, content, provider, and version guides,
  plus an exact provider example. Existing exported guides are never
  overwritten. Forge 61 Eclipse launches use disjoint `bin/default`,
  `bin/main`, and `bin/test` outputs; if Eclipse removes staged guide copies, the
  exporter reads the authoritative source-checkout guides without weakening
  packaged-jar validation.
- Added independent, atomic migration of valid non-default legacy ore settings
  into a Mineralogy OreSpawn provider override, including deterministic reports
  and exclusive-to-inclusive maximum-height conversion.
- Mineralogy 6.0 JSON upgrades now retain the original global and per-world
  geology files byte-for-byte while mapping their old block-named rock and ore
  entries onto Mineralogy's stable provider rule IDs. This prevents duplicate
  ore generation and preserves world-specific geology choices on first start;
  established OreSpawn files remain authoritative and reloads are byte-stable.
- Converted every data registry to Minecraft 1.21's singular `recipe`,
  `advancement`, `loot_table`, and `tags/item|block|fluid` directories; release
  audits reject stale plural registry paths.
- Replaced the removed JavaScript coremod service with required Mixins for the
  legacy state tables, selected-world level data, chunk conversion, and
  populated-boundary protection. Legacy block states are written through the
  target-native NBT operations while preserving all 18,192 mappings.
- Preserved 1.21.11-native wall tall-side blockstates and models, wall/item tags,
  loot tables, fluid APIs, rendering setup, resource format 75.0, and data
  format 94.1 resources.
- Added reproducible Java 21 main, sources, and Javadoc artifacts, exact released
  OreSpawn dependency verification, guarded 1.21.11 CI, and the four-component
  release tag `6.1.2.121111`.
- Kept ForgeGradle 7 while sealing Forge 61's audited zero-repair Mavenizer
  fixture by SHA-256. The build-only tool runs on Java 25; Mineralogy compiles
  and ships exclusively as Java 21, and release audits reject fixture leakage.
- Isolated CI's verified OreSpawn artifact in an exclusive Gradle repository so
  dependency resolution cannot fall through to an unverified public copy.
  Release verification also enforces Maven coordinate
  `zone.moddev.mc:Mineralogy`, its generated POM, and the jar's
  `Maven-Artifact` manifest entry.
